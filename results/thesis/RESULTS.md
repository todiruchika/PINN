# FNO/PINO thermal-map reconstruction: results

Branch: `siya-fno-pino`. Code: `src/models/fno_pino.py`, `src/physics/grid_residual.py`, `src/train/fno_pino.py`.
Figures and tables in this folder are generated by `src/eval/thesis_figures.py`; heatmaps by `src/eval/heatmaps_fno.py`.

## 1. Problem

Reconstruct a chip's full 128×128 temperature map from 5, 8 or 10 noisy sensor readings (σ = 1 °C, 1 °C quantisation),
given the known ambient temperature. The die obeys the steady heat equation with temperature-dependent conductivity
and adiabatic (no-heat-flow) lateral edges. Metrics are computed on non-sensor nodes only, on the 100 test chips.

## 2. Method

**Model: Fourier neural operator (FNO) trained as a physics-informed operator (PINO).**

- Input: a 128×128 image with five channels: normalised sensor readings at sensor pixels, a sensor mask, the ambient
  temperature, and the x and y coordinates.
- Output: two maps. θ is the temperature rise over ambient divided by 50 K. q̃ is the heat source divided by h_eff·50 K.
  The source map is needed because the heat source is unknown at test time. Only θ is scored.
- Architecture: 1×1 lift to 32 channels, 4 Fourier layers (8 retained modes per direction), 1×1 projection. 533,186 parameters.
- Loss: `w_temp · MSE(θ) + w_src · MSE(q̃) + w_phys · mean(R²)`, where R is the finite-volume residual of the heat equation
  on the grid. The physics weight ramps up over the first 20% of training. Adiabatic edges are built into the scheme.
- Optimiser: AdamW, learning rate 1e-3 with cosine decay to 1e-5, batch of 8 chips, gradient clipping at 1.0.
- Model selection: the checkpoint with the lowest validation error is kept. The test set is scored once.

**Final configuration:** source-loss weight 0.1, physics weight 0.01, 8 modes, 3000 steps.

## 3. Data and budget

- Split: 500 train / 100 validation / 100 test chips (`data/raw/dataset/splits.csv`), POD-QR sensor placement.
- Training budget: 3000 steps × batch 8 ≈ 48 passes over the 500 training chips. About 0.4 s per step on a 22-thread
  CPU with no GPU, roughly 20 minutes per run when run alone.

## 4. Results

### 4.1 Final configuration across sensor counts (test set)

| Sensors | Relative L2 error | MAE (°C) | Peak error (°C) | Hotspot error (cells) | Seeds |
|---|---|---|---|---|---|
| 10 | **9.78% ± 0.20** | 4.02 ± 0.11 | −8.48 ± 0.37 | 20.6 ± 1.4 | 3 |
| 8 | 10.79% | 4.45 | −9.76 | 28.1 | 1 |
| 5 | 13.20% | 5.46 | −14.02 | 34.5 | 1 |

Peak error is the predicted maximum minus the true maximum (negative = underestimate). One hotspot-error cell is
12 mm / 127 ≈ 0.09 mm. The ± values are standard deviations over seeds.

### 4.2 Effect of the source-loss weight (10 sensors)

| Setting | Relative L2 error | MAE (°C) | Peak error (°C) | Hotspot error (cells) | Seeds |
|---|---|---|---|---|---|
| Source weight 1.0 (first baseline) | 10.64% ± 0.25 | 4.49 ± 0.14 | −8.45 ± 0.18 | 21.5 ± 0.5 | 3 |
| **Source weight 0.1 (final)** | **9.78% ± 0.20** | **4.02 ± 0.11** | −8.48 ± 0.37 | **20.6 ± 1.4** | 3 |

Lowering the source weight reduces the error by about 0.9 points. That is roughly four times the seed spread, so the
improvement is consistent across seeds.

### 4.3 Ablations (10 sensors, seed 0 unless stated)

| Variant | Relative L2 error | MAE (°C) | Peak error (°C) | Hotspot error (cells) | Notes |
|---|---|---|---|---|---|
| Final configuration (3-seed mean) | 9.78% | 4.02 | −8.5 | 20.6 | reference |
| Physics weight 0.1 | 13.64% | 5.93 | −13.1 | 28.0 | worse: stronger physics pulls the fit away from the data |
| 16 Fourier modes | 10.74% | 4.53 | −8.1 | 20.2 | no overall gain |
| Hot-pixel loss weight 4 | 9.74% | 4.07 | −7.0 | 19.1 | peak underestimate shrinks by 1.7 °C, overall error unchanged |
| 10,000 steps (source weight 1.0) | 9.98% | 4.11 | −7.6 | 19.6 | longer training helps only a little |

At 5 sensors, the hot-pixel weighting gave 13.36% against 13.20% without it, with a peak error of −12.7 °C against −14.0 °C.
It improves the peak but not the overall fit, so it is not part of the final configuration.

### 4.5 What the heatmaps show

The generated maps follow the broad warm regions, and the sensor readings constrain the field near the sensors.
The main failure is at the hotspot. Generated peaks are lower and more spread out than the true peaks, and the
error is largest in the hottest region. The problem gets worse as sensors are removed: at 5 sensors the hottest
chip's peak is about 78 °C where the truth is 120 °C. The hotspot location error is about 20 cells at 10 sensors,
or roughly 2 mm, so the warm area is found but its exact centre is not.

## 5. Comparison with the teammates' models

These are the numbers reported on their branches. I haven't checked that their metric code is identical to ours,
and their budgets differ, so treat the comparison as indicative only.

| Model (branch) | Sensors | Relative L2 error | Budget | Seeds |
|---|---|---|---|---|
| FNO/PINO (this work) | 10 | 9.78% | 3000 steps × 8 chips ≈ 48 passes | 3 |
| DeepONet (`smriti`) | 10 | 6.1% | 400 epochs (≈6,250 steps × 32 chips) | 5 |
| FNO/PINO (this work) | 8 | 10.8% | 3000 steps × 8 chips ≈ 48 passes | 1 |
| DeepONet (`smriti`) | 8 | 8.6% | 400 epochs | 5 |
| FNO/PINO (this work) | 5 | 13.2% | 3000 steps × 8 chips ≈ 48 passes | 1 |
| DeepONet (`smriti`) | 5 | 11.5% | 400 epochs | 5 |

Under this budget, FNO/PINO is behind the DeepONet at 8 and 10 sensors and slightly behind it at 5 sensors.
Its training budget is much smaller, and the 10,000-step run only gained 0.4 points, so budget alone does not
explain the gap. The data-driven PINN on `data-driven-pinn` has only a 3000-step check, so it is not comparable.
The per-chip PINN on `ruchika-per-chip-pinn` fits one network per chip, so it is not comparable either.

## 6. Limitations

- **Seeds:** the 5- and 8-sensor results are single runs. The 10-sensor results use three seeds.
- **Budget:** 3000 steps is about 48 passes over the training chips, far below the teammates' budgets.
- **Physics weight:** 0.01 was not tuned. The only other value tested (0.1) was worse.
- **Noise:** the model trains on the stored noisy readings. The teammates re-draw the sensor noise at each step,
  which we have not done.
- **Physical constants:** the die thickness (500 µm), effective heat-sink conductance (6256 W/m²K) and leakage
  coefficient (0.012 /K) are marked "ASSUMPTION — NOT SOURCED" in `PROTOCOL.md`. The physics term uses these values.
- **Hotspot sharpness:** the FNO keeps only a few Fourier modes, which smooths sharp features. Raising the mode count
  to 16 did not fix this, so the hotspot shortfall has other causes too.
- **Hardware:** all runs are CPU-only. Several runs shared the CPU, so the reported run times are not clean timings.

## 7. Reproducing the final results

```
python -m src.train.fno_pino --sensors 10 --seed 0 --steps 3000 --out results/fno_pino_wsrc0.1
python -m src.train.fno_pino --sensors 8  --seed 0 --steps 3000 --out results/fno_pino_wsrc0.1
python -m src.train.fno_pino --sensors 5  --seed 0 --steps 3000 --out results/fno_pino_wsrc0.1
python -m src.train.fno_pino --sensors 10 --seed 0 --steps 3000 --w-src 1.0 --out results/fno_pino   # baseline
python -m src.eval.heatmaps_fno results/fno_pino_wsrc0.1/N10_seed0/best.pt results/fno_pino_wsrc0.1/N10_seed0/heatmaps.png 4
python -m src.eval.thesis_figures
```

The default source-loss weight is now 0.1, so the first command doesn't need the flag.
